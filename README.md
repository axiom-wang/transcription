# Mac 本地音频转写

在听记中点击「立即扫描」，发现 Mac 上从 iCloud 同步下来的新旧语音备忘录，复制后生成带时间戳的完整转写、优化后的转写交付稿和分析稿。Qwen3-ASR 与 Qwen3.5 文本模型都在 Mac 本机运行，音频和文字不会发送到语音识别或大模型服务。

当前默认语音识别模型为 **Qwen3-ASR-1.7B 完整精度（FP16，未量化）**，配合 Qwen3-ForcedAligner-0.6B 提供词级时间戳；使用 Apple Silicon 的 Metal GPU 本地运行。文稿优化与分析采用 Qwen3.5-9B 的 4 位量化版，转写和文本模型依次运行。日常启动无需联网、无需安装 FFmpeg、无需打开 Docker。

## 可视化工作台

日常直接打开 **应用程序 → 听记.app**，也可以通过 Spotlight 搜索“听记”，或把应用拖到 Dock。应用会自动启动或复用本地工作台服务，直接在独立的 macOS 应用窗口内显示资料库，不启动浏览器，也不会弹出终端窗口。

本机已安装到 `/Applications/听记.app`（无系统应用目录写权限时，安装器使用 `~/Applications/听记.app`）。应用复用本项目中的运行环境、模型与资料，不复制大型模型。请保留项目目录；移动项目后，在新位置运行 `.venv/bin/python scripts/build_workbench_app.py` 更新应用入口。

应用支持原生文件选择和保存面板、复制粘贴、`⌘O` 导入、`⌘S` 保存笔记、`⌘W` 关闭窗口和 `⌘Q` 退出。关闭前会检查未保存笔记与未完成文件传输；再次点击 Dock 图标可显示原窗口。重新安装使用 `.venv/bin/python scripts/build_workbench_app.py`，安装器通过本机 Swift 工具链编译原生外壳，已有资料与模型保持原位。

命令行和原有脚本仍可作为可选的浏览器入口使用：

```bash
./run.sh workbench --open
```

应用内置工作台界面。本地服务默认地址为 `http://127.0.0.1:8765`，只监听本机。启动入口会建立本地访问会话，请通过入口首次打开；直接访问地址而没有会话时，不会暴露录音资料。前端无 CDN、在线字体或第三方请求，日常使用可完全离线。

- **资料库**：同一音频内容的多次识别按版本收纳，支持名称/原文预览搜索、排序、收藏、归档和批量导出完整 TXT。
- **录音详情**：整理稿、带时间戳的转写原文、分析稿、我的笔记；点击时间引用展开原文，再播放相应位置。支持倍速、前后 10 秒与原文内搜索。
- **处理队列**：分别展示语音识别和文稿状态、实际处理阶段、最近活动、已处理音频时长或文本分段；没有真实进度时明确提示。可优先处理或取消尚未开始的工作台请求。
- **需要处理**：展示导入权限错误、转写失败、文稿失败与已有的待核对项。文本失败不影响原稿阅读，可仅重试文稿阶段。
- **导入与导出**：拖入窗口或选择多个文件，按音频内容去重。单文件上限 2 GB。可单独导出 TXT、Markdown、SRT、JSON，或批量打包完整转写 TXT。
- **个人笔记**：独立保存，有保存状态和多窗口冲突检测。未保存时离开页面会提醒。重新生成文稿不会覆盖笔记。
- **历史文稿**：重新生成或切换文本处理版本时，保留此前交付稿和分析稿，可从详情中的「历史文稿」下载。
- **录音名称**：文稿生成时，本机文本模型根据转写内容写一句话简介，录音名称变为「一句话简介 + 录制时间」（如「讨论首版范围与预算提议 2026-10-16 13:00」），`转写TXT` 文件名与索引同步更新。已有文稿的旧录音会在后台逐条补齐名称，不重新生成文稿。手动「重命名」优先；详情中「重新生成名称」可单独重来，也可运行 `./run.sh enrich --title <任务指纹>`。
- **说话人名称**：在转写原文中点击说话人，或在详情侧栏「说话人」中改名，改一次即同步到这条录音的全部发言、整理稿、分析稿、下载和 `转写TXT`。留空恢复默认编号。生成文件本身不改，名称在读取和导出时套用。
- **发送给 Agent**：详情页「发送给 Agent」把转写原文（可选整理稿、分析稿）整理成 `录音上下文.md`，保存在 `state/agent-context/<任务指纹>/`，并在「终端」中启动 Claude Code 或 Codex 先读完它，随后即可围绕录音提问。也可复制上下文粘贴到任意 Agent 应用，或下载 .md。未安装对应命令时终端会给出安装方式。
- **删除**：列表行、批量操作和详情侧栏都可删除，删除前有确认弹窗。删除转写、文稿、笔记和全部版本，再次扫描也不会重新转写；勾选「同时删除录音源文件」时，工作台导入或手动转写的原音频移到「废纸篓」，可恢复。语音备忘录 App 中的原录音不受影响，需要时请在 App 内删除。再次手动导入同一文件会恢复转写。

“暂停后续”在文件/文稿任务边界生效，当前推理继续完成，不提供单条音频中途无损暂停。暂停影响后续转写与文稿处理，不关闭 Apple 的同步，也不删除任何资料。已经启动的旧版本进程需要本轮结束后才会读取新控制机制。

工作台请求持久保存在 `state/workbench.sqlite3`，只在工作台服务运行时调度。关闭应用窗口或退出听记不会终止已经开始执行的操作；电脑重启后，重新打开入口即可恢复等待中的请求。正在执行的操作在独立进程运行；中断后会保留结果并提示检查重试。不再有后台定时扫描；CLI、拖拽入口和工作台共用转写及模型锁。

通过工作台上传的音频副本保存在 `state/workbench-audio/`，不会混入语音备忘录扫描目录，因此取消排队后不会被下一次扫描重新拾取。归档仅隐藏资料，不删除音频或文稿。浏览器不支持的音频可点击「生成本地兼容音频」，使用已安装的 PyAV 转成缓存 WAV；原音频保持不变。副本/原文件与原稿内容指纹不一致时，不会播放错配的音频。

新增文件位置：

- `state/workbench.sqlite3`：收藏、标题、归档、笔记及笔记历史、操作请求。
- `state/workbench-control.json`：共享暂停状态。
- `state/activity/`：真实处理阶段与进度。
- `state/workbench-preview/`：按需生成的兼容播放缓存。
- `output/<任务指纹>/history/`：已被新版本替换的交付文稿快照。

备份时请同时保留原始录音、`output` 与 `state`；SQLite 使用既有备份注意事项。需要排查工作台启动问题时查看 `state/logs/workbench.log`。

```bash
node --check src/audio_notes/web/app.js
node --test tests/workbench_frontend.test.cjs
# 独立的合成录音 UI 预览，不读取私人录音，不启动模型：
```

## 日常使用：手动扫描 iCloud 语音备忘录

项目不再在后台定时扫描。在 Apple 设备上用「语音备忘录」录音，等 Apple 的 iCloud 同步把录音下载到 Mac 后，**打开听记，点击资料库右上角或「设置与运行环境」里的「立即扫描」**。无需手动导出或放入 inbox。

每次点击跑一轮完整流程：读取 Mac 的语音备忘录同步目录，把新增或修改后的音频复制到本项目，用本地语音识别模型转写，再按配置做说话人区分和文稿整理与分析，更新索引和 `转写TXT`，然后结束，不会常驻或定时重复。首次扫描也会接收旧录音，处理顺序优先较小的文件。仍在同步的文件最多等待 `settle_seconds` 再加 30 秒；超时后本轮照常结束，并提示稍后再扫描。扫描进行中按钮显示「扫描中…」，重复点击不会重复排队。扫描结束时会提示本轮发现、转写、失败和等待同步的数量，处理队列里也保留这条记录。

旧版本安装过的每 60 秒自动扫描服务（`~/Library/LaunchAgents/local.audio-notes.voice-memos.*.plist`）会在打开听记或运行新版 CLI 时自动停用并删除，日志中记一条；也可以手动运行 `./run.sh service uninstall` 清理。

**打开项目根目录的 `转写TXT` 文件夹，即可直接查看所有已完成录音的简体 TXT。** 文件名采用「录音名称（短标识）.txt」，同名录音不会互相覆盖。每条录音完成后自动汇集；删除或损坏的 TXT 会在下一次扫描时从已有结果补齐，无需重新识别。该文件夹与 `output` 位于同一目录；详细结果中的原始 TXT 仍保留。

打开 `output/index.md` 查找完成的阅读版和完整稿。每完成一条就更新索引。`inbox/voice-memos/` 是程序自动管理的音频副本区，原文件保持只读；编辑后的录音产生新内容指纹，旧版本和旧文档保留。

默认会在**开始转写、转写完成、转写失败**时发送 macOS 系统通知，并播放提示音。通知只包含录音名称和结果提示，不展示转写正文。手动扫描、命令行运行和持续监控均适用；重复扫描已完成录音、仅修复已完成文档时不再提醒。通知发送失败会写入日志，不影响转写。

可运行 `./run.sh notify-test` 发送测试通知。若未看到横幅，请在「系统设置 → 通知」中检查「脚本编辑器」（Script Editor/osascript）的通知权限，并检查专注模式；系统可能仅将通知放入通知中心。程序返回成功仅表示系统已接受发送请求。将 `config.toml` 的 `[notifications]` 下 `enabled = false` 可关闭通知；下一次扫描会读取新配置。

苹果的同步与识别是两个独立环节：iCloud 下载录音需要 Apple 的网络同步，语音转写始终在本机执行，不调用云端识别服务。项目不会请求 Apple 账户密码，不访问其他 iCloud Drive 文件，不写入苹果的录音数据库。

```bash
./run.sh status             # 查看导入与转写状态
./run.sh service status     # 检查是否残留旧的后台自动扫描服务，并显示实际 Python 路径
./run.sh service uninstall  # 清理旧的后台自动扫描服务；音频和文档保留
```

`service install` / `service start` 已停用，执行时只提示改用听记手动扫描。`启用自动转写.command` 和 `持续监控.command` 现在只打印说明并清理旧服务。

不打开听记时，也可以双击 **开始转写.command** 或运行 `./run.sh`，效果与一次手动扫描相同：先导入，再转写，然后结束。另一实例正在转写时，运行锁会提示已有任务；可直接查看状态和结果。`./run.sh watch` 仍保留给需要前台持续监控的高级用户，任何默认入口都不会调用它。

普通外部音频仍可额外放入 `inbox`，与自动导入的语音备忘录一并处理。

## 手动转写某个录音

项目文件夹里的 **手动转写.app** 支持两种用法，无需打开终端：

1. **双击应用，选择录音文件**，可按住 `⌘` 多选。
2. **把录音直接拖到应用图标上**，也可以一次拖入多个文件。

开始、完成和失败时会发送系统通知。成功后会在 Finder 中定位转写交付稿 `polished.md`；文字阶段未完成时定位保留原文的阅读版 `notes.md`。多文件时定位 `output/index.md`，双击即可打开。只处理选中的文件，不触发语音备忘录导入，也不扫描其他录音。原录音保持原位、只读，不需要提前复制进 `inbox`。相同内容已有结果时直接复用；原录音移动后，文档中的音频链接可能需要手动调整。

如果另一个任务正在转写，手动任务会提示已排队，等当前实例结束后自动继续，无需重复拖入。文件还在保存或下载时会等待稳定后开始。格式不支持、文件为空或转写失败时会弹出中文提示。

支持 M4A、MP3、WAV、MOV、MP4、AAC、AIFF、AIF、CAF、FLAC（以配置中的扩展名为准）。请将应用保留在项目文件夹里；可把它拖到 Dock 便于使用。入口可通过 `.venv/bin/python scripts/build_manual_app.py` 重新生成，首次 `setup.sh` 也会创建。

命令行同样支持指定文件：`./run.sh transcribe --reveal -- "/路径/某条录音.m4a"`。原有「开始转写.command」仍用于批量处理全部待转写录音。

## 首次扫描前的准备

Mac 的「语音备忘录」需启用 iCloud 同步，并且录音实际下载到了 Mac。仅云端占位或零字节文件会等待同步，不会当作完整录音处理。Apple 的目录布局可能随系统升级变化，源目录可在 `[voice_memos].directories` 中调整。

macOS 的隐私保护可能拒绝读取语音备忘录目录。开启「系统设置 → 隐私与安全性 → 完全磁盘访问权限」：

- 在听记中扫描：允许「听记」。仍被拒绝时，再添加 `./run.sh service status` 显示的 **Python 实际可执行文件**（添加窗口按 `⌘⇧G` 可输入完整路径；Homebrew 更新 Python 后路径可能变化），然后重启听记并重新扫描。
- 从 Codex 或终端运行：允许对应的 Codex/终端应用。

读取失败会显示在听记的「需要处理」页，附带具体目录和「重新扫描」按钮。

```bash
./run.sh discover       # 只读检查本地录音目录和访问错误
./run.sh import         # 仅复制新旧录音，不做识别
```

转写不会偷偷安装依赖或下载模型。

同步目录每条录音的大小、修改时间、文件属性变化时间和 inode 记入 `state/imports.sqlite3`；未变化的文件不会再次复制。复制时计算 SHA-256，并在结束时再次检查源文件是否改变。临时文件留在隐藏暂存区，复制完整后才原子发布给转写器；删除了副本或副本被修改时，会重新读取原文件修复。自带的波形、缓存、恢复目录和隐藏文件不进入转写队列。

录音名称、录音日期和标识从 Mac 上实测的 `CloudRecordings.db` 已知字段读取，数据库始终以只读模式打开并支持读取 WAL。系统结构不兼容时退回原始音频文件名，仍能处理音频；不推测加密标题或未知标志位的含义。Markdown 保留原始录音路径及副本路径，`recorded_at` 只来自实际数据库值，`created` 为转写生成时间。

## 每条录音的产物

文档保存在 `output/<任务指纹>/`；文件夹指纹用于防止重名覆盖，标题仍为录音名称。`output/index.md` 提供可读的统一入口。

| 文件 | 内容 |
| --- | --- |
| `raw.json` | 完整模型输出，包括原始逐段文字、段起止时间、词级时间戳、引擎提供的附加信息、识别参数、音频 SHA-256、源路径、时长、模型信息 |
| `transcript.md` | 模型原始完整逐段转写，保留原始简繁字形与每段起止时间 |
| `transcript.simplified.md` | 简体完整逐段稿，保留全部识别内容与相同时间戳 |
| `notes.md` | 简体阅读版：保留全部识别内容，按停顿与长度合并为段落，按时间分节，链接回简体完整稿 |
| `transcript.srt` | 保留模型原始字形的 SRT |
| `transcript.txt` | 原始逐段纯文本 |
| `transcript.simplified.srt` / `transcript.simplified.txt` | 简体字幕与纯文本，英文和时间戳保留 |
| `polished.md` / `polished.txt` | 文本模型生成的优化交付稿及其纯正文，含原文引用、修订记录和待核对项的版本为 Markdown |
| `analysis.md` | 文本模型生成的速览、主题分析、原文行动、待确认问题及单独标明的模型推断与建议 |
| `complete.json` | 原始转写完成标记和产物校验值，用于恢复与完整性检查 |

各份 Markdown 都带 YAML 元数据，可放进 Obsidian 等知识库。`created` 是转写生成时间；自动导入的语音备忘录另外记录来自 Apple 数据库的 `recorded_at`，无元数据时不推测录音日期。源文件和副本链接对应首次生成时的位置，搬动文件后需按实际位置查找。相同字节内容的副本共用一套文档，各路径另记在任务数据库 `sources` 表。

**整理规则：**阅读版和简体完整稿用本地 OpenCC `t2s.json` 做标准繁简转换，再折叠空白、合并相邻段落、保留时间引用、按时间编号章节；不替换地区用语。不新增主题、结论、人物身份、事实或待办；不删去口头禅、重复句，也不自动改写疑似识别错字。不使用生成式大模型做整理，因此不存在整理阶段的自由补写。语音模型的识别本身仍可能出现错字、漏字或幻听，时间戳也是估计值；重要内容须对照录音，原始结果一直保留。底层模型参数中的 Infinity 等非有限数值以 `{"$float":"inf"}` 形式保留，确保 JSON 标准合法，不影响转写文字。

`language = "zh"` 只指定中文，不能保证输出简体；提示词也不能可靠固定简繁。项目在文档生成阶段统一转换，日常完全离线。转换只处理正文和显示标题，文件路径、链接、音频指纹、时间戳及 `raw.json` 均不改动；模型原始 Markdown、字幕、纯文本另行保留。索引默认指向简体完整稿。升级前已完成的录音会在下一轮扫描复用原始缓存补齐简体产物，不重新识别。正在转写的任务继续执行，结束后下一轮扫描应用新规则。

生成的文档是自动产物。需要手工批注时请复制到自己的知识库再编辑；产物被改动或缺失时，下次运行会从原始缓存重建。

## 命令

```bash
./run.sh                     # 默认 run：批量处理一次
./run.sh run                 # 等待同步稳定，处理新任务并重试之前失败/中断的任务
./run.sh run --no-wait       # 只处理当前稳定的文件；不等待同步
./run.sh watch               # 持续扫描；失败任务按配置间隔重试
./run.sh status              # 查看任务统计、错误和日志位置
./run.sh doctor              # 检查模型完整性、依赖和本地 GPU 加载
./run.sh download-model      # 首次联网准备模型；已有完整模型则直接跳过
./run.sh download-model --refresh  # 强制重新下载模型文件以修复损坏（需要联网）
./run.sh --config config.local.toml run  # 使用其他配置
```

退出码：`0` 成功（也包括无新任务）；`1` 某些文件失败，其余仍处理；`2` 配置、环境或运行锁错误；`3` 使用 --no-wait 时有文件待同步；`130` 用户停止。双击入口会保持终端窗口，方便阅读错误。

## 配置与模型

编辑 `config.toml`，或复制为 `config.local.toml`。相对目录始终相对于配置文件，而非终端当前目录。四个目录必须互不重叠，避免音频和输出混在一起。

```toml
[paths]
inbox = "/Users/你的用户名/录音待转写"
output = "/Users/你的用户名/Documents/录音知识库"
state = "state"
models = "models"
```

支持 `m4a`、`qta`、`mp3`、`wav`、`mov`、`mp4`、`aac`、`aiff`、`aif`、`caf`、`flac`。语音备忘录生成的 `.qta`（QuickTime 音频容器）可直接自动导入或手动转写，无需改名或预先转换格式。容器必须含可解码音轨；不根据扩展名假定内部编码正确。视频读取第一条音轨，不处理画面，不识别讲话者身份。

默认 `model = "qwen3-asr-1.7b"`、`compute_type = "float16"`，由 MLX 在 Apple GPU 上运行。识别模型与时间戳模型权重约 6.5 GB，下载固定版本并保存各文件 SHA-256。只从本地路径加载，不执行模型仓库里的远程代码。保留 `[whisper]` 段名以兼容现有入口；`cpu_threads`、`beam_size` 和 `condition_on_previous_text` 仅对旧 Whisper 引擎有效。

本次选择针对 M5 / 16 GB Mac 上的中文、中英混合及日常长录音，优先准确率，采用未做 4/8 位量化的权重。没有所有语言、场景都第一的模型：[Qwen 官方评测](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)显示它的中文和多语言表现强于 Whisper large-v3；[FireRedASR2 官方评测](https://github.com/FireRedTeam/FireRedASR2S)中，FireRedASR2 在部分中文数据集上更好。因此这里采用的是综合 Mac 部署、语言覆盖、标点和时间戳能力后的方案，不宣称全场景绝对第一。

长录音先由本地 Silero VAD 检测语音区间，再按低能量边界切为不超过 30 秒的小段，时间戳还原到原录音位置。对齐后的词不会替换识别原文，原文的标点完整保留。若生成达到长度上限或缺失词级对齐，任务报错，不将不完整结果标记为成功。

旧 Whisper small 权重和对应旧稿已按需清理。需要切回时，设 `model = "small"`、`compute_type = "int8"`，再运行 `./run.sh download-model` 重新下载；也支持 `tiny/base/medium/large-v3/turbo` 的 CPU 推理。模型与依赖锁定在本地；日常运行不会自动更新。

- `language = "zh"`：默认，中文为主，可保留中英文混合，不翻译成英文。
- `language = "en"`：英文为主。
- `language = "auto"`：由模型检测主要语言；短录音或严重混合语言时可能检测错误。
- `initial_prompt`：可填写确知的专有名词；提示可能影响识别，不应放入推测的录音内容。
- `vad_filter = true`：本地语音活动检测，减少长静音的无效识别；很轻的讲话可能被漏检，必要时可改为 `false` 重跑。
- `timeout_seconds = 0`：默认无单文件超时；如需防止异常文件一直占用，可设秒数。

更改模型、识别参数、模型权重或关键推理库版本会产生新的任务指纹和独立输出，不覆盖旧结果；相同指纹不重复识别。更改 Markdown 分段参数仅重建文档，复用原始结果。

音频优先按文件大小串行识别，每条录音独立启动子进程，隔离解码错误、原生库崩溃和内存问题。批量是多个文件自动依次处理，不是多个模型同时争抢内存。模型每文件重新加载有一定开销。非常长的录音仍需足够内存，因为底层会解码整条音频。


## 恢复与故障排查

转写任务 SQLite 位于 `state/jobs.sqlite3`，自动导入记录另在 `state/imports.sqlite3`，最近扫描报告在 `state/voice-memos-status.json`，记录任务指纹、状态、尝试次数和错误；`state/logs/workflow.log` 是总日志（自动轮转），每条录音另有 `<任务指纹>.log`，记录加载、解码、识别进度和详细错误。可在另一个终端用 `tail -f` 查看。

- **正常停止/断电后重跑：**以文件为单位续跑，已完成文件跳过。已保存 `raw.json` 的任务不再识别，继续生成文档；没有完整原始缓存的录音会从头识别。没有声称单条长录音内的逐段断点续算。
- **某个文件失败：**日志会指出该文件；继续处理其他文件。修复原文件或环境后再次运行即可；同一轮等待扫描不会反复重试已知失败。`watch` 默认 5 分钟后重试，避免不断循环报错。
- **缺失或损坏的 Markdown：**重新生成，不调用语音识别模型；损坏的原始 JSON 移为 `raw.invalid-*.json` 留存，再转写。
- **模型损坏/未安装：**运行 `download-model --refresh` 或 `download-model`。模型完整性由 SHA-256 校验，不只检查文件存在。
- **另一个实例正在运行：**关闭已有 run/watch。锁会随进程释放，不需要删除锁文件。若主进程被强制杀死，仍在工作的子进程持有锁，等它完成再重跑。
- **音频仍在同步：**run 会自动等待最后修改后的 30 秒再继续；转写结束会再次检查内容指纹，变化时不保存此次结果。
- **一直没有新任务：**检查配置指向的 `inbox`、扩展名、文件是否隐藏或尚未实际下载到 Mac。

输出采用同目录临时文件、落盘、原子替换，并在全部产物生成后写入完成标记；数据库完成状态最后更新。运行锁阻止双击多次造成并发写入。

## 本地文稿优化与分析

在原始转写之外，使用 **Qwen3.5-9B / 4 位量化 / MLX** 生成两份面向阅读和使用的材料。针对这台 M5 / 16 GB Mac，选择约 6 GB 的量化模型，给系统、输入上下文和推理缓存留出余量。它是当前采用的本机方案，不代表已经比较所有模型或保证任何场景准确率第一。转写和文本处理共享模型资源锁，依次使用 GPU；文本模型在独立 `.venv-text` 环境、独立子进程中运行，用完退出释放内存，不改变现有语音模型的依赖。

每条录音新增以下产物，统一从 `output/index.md` 进入：

| 文件 | 用户用途 |
| --- | --- |
| `polished.md` | **转写交付稿**：完整整理口头表达，修正有上下文依据的错词、标点和语序；保留信息与顺序，附原文时间引用、自动对比的部分字词修订记录及待核对项 |
| `polished.txt` | 交付稿的纯正文版本，便于复制和分享；无修订附注，重要内容应结合 Markdown 核对 |
| `analysis.md` | **分析稿**：一句话主旨、速览要点、主题展开、进一步分析、原文中的行动/要求/条件、待确认问题和可选建议；没有内容的章节省略 |
| `enrichment.complete.json` | 文本模型、版本指纹、生成时间、性能信息与交付文件校验值 |
| `enrichment.status.json` | 待处理、运行、失败/完成的阶段状态；与语音转写状态独立 |
| `enrichment/<指纹>/` | 分段润色、分段分析、汇总和最终结构化结果，供中断恢复与检查使用 |

个人思考侧重思路与卡点；会议侧重提议、共识、决定和行动的区别；学习侧重观点、论据及适用条件。混合内容无需提前选择模板。分析以**原始转写**为依据，避免把润色中的误改继续当成事实。模型推断与额外建议独立标注，不冒充原话；负责人、期限未明确时不补写。每个分析条目附原文段落链接。分析使用有长度预算的模型推理模式，达到预算后转入完整成稿；交付文件只保留最终结果。原稿没有说话人标签时，使用“对话中提到”等中性表述，不根据被提及的人物猜测谁在发言。

润色不是重新识别音频。文本模型无法听出原转写漏掉的内容；只能在上下文有明确依据时修正字词。提示要求保留否定、条件、疑问、不确定性和观点归属，不把“可能考虑”改成“决定执行”。数字字面值、原文单元覆盖、顺序、引用编号、修订记录匹配和输出完整性会进行程序检查；不通过时修复重试，仍失败则保留原稿和进度。**这些检查不能保证语义完全无遗漏、纠错一定正确、引用真正支持模型判断。重要材料仍须核对录音。**

`notes.md`、完整逐段稿、字幕、`raw.json` 以及「转写TXT」仍保留原有完整转写用途。优化交付稿的纯文本另在各录音目录的 `polished.txt`，不会把原始 TXT 静默替换成模型改写版。所有自动生成稿件均可能被重新生成；个人批注请另存独立文档，不写入这些自动文件。

首次安装文本能力：

```bash
./setup-text.sh
```

安装会下载固定仓库版本的模型，并记录 SHA-256；独立环境的全部依赖锁定在 `requirements-text.lock`。日常推理只加载本地路径，强制 Hugging Face / Transformers 离线，不启动包管理器、不自动更新、不上传转写内容。`check-text-model` 校验全部文件，后台每次处理前检查清单和文件大小。

在 `config.toml` 设置：

```toml
[analysis]
enabled = true
chunk_chars = 4000
max_input_tokens = 16000
max_output_tokens = 6000
timeout_seconds = 3600
retry_seconds = 600
max_jobs_per_scan = 1
```

新录音先完成原始转写并可阅读，批次转写后再优化与分析。每次手动扫描都会补齐全部待生成文稿，按较新的任务优先（可选的 `watch` 模式每轮最多处理 `max_jobs_per_scan` 条）。单个文本任务处理期间后续录音会等待；该版本不抢占正在执行的模型推理。分析稿的速览、主题要点和行动内容使用程序从所引原文选取的完整句子，以原话摘录呈现，并检查摘录确实存在于对应原文。主旨按主题构成，模型的推断、问题和建议独立标明。原话本身仍可能有错误或偏见，并未外部验证；模型选取的重点与推断也可能有偏差，不能替代人工核对。文本失败不会把语音转写标成失败，索引显示待重试，过了冷却时间后的下一次扫描会重试。手动选择录音时，会处理所选录音的全部待生成文稿；成功后在 Finder 定位交付稿，文本阶段未完成时定位原阅读版。

```bash
./run.sh check-text-model          # 完整校验本地文本模型文件
./run.sh enrich                    # 给已有转写补齐两份稿件，不重新识别音频
./run.sh enrich <完整任务指纹>      # 仅处理某条已完成转写
./run.sh enrich --force <任务指纹>  # 保留旧缓存，重新生成
./run.sh status                    # 分别查看转写与文稿处理状态
```

手动 enrich 可以在后台批次转写时提交，只处理已完成的原稿；它有独立的文稿任务锁，与转写共享模型资源锁，等当前推理释放资源后继续。拖拽转写入口沿用原有排队机制。模型、提示、分段设置、依赖锁或原文变化会生成新的文本处理指纹，复用语音结果。中断后复用已成功生成的分段；失败的生成不会写入完成标记。生成文件缺失/损坏时优先从结构化缓存重建；结构化结果损坏则保留损坏副本，再尝试重建。

实际离线推理验证使用合成的混合录音文字，不读取私人录音：

```bash
sandbox-exec -p '(version 1)(allow default)(deny network*)' \
  .venv/bin/python scripts/verify_text_model.py
```

最新验证目录记录在 `verification/text-model-latest.txt`。生成速度与内存值只适用于该样本，不能推算所有长录音耗时。

润色按较细的原文块处理（每块最多 4 个原文单元且不超过约 600 字），原文定位与覆盖由程序负责；分析按 `chunk_chars` 使用更大的上下文，并在长文时汇总分段分析，最终事实要点仍须是可核对的原话摘录。模型输出的结构化材料只做已知字段缺失引号的有限格式修复，不补正文、括号或截断结果；最终内容仍要通过结构、引用和完整性检查。

### 区分说话人

新增本地 `pyannote/speaker-diarization-community-1`，使用独立 `.venv-speakers` 环境，
与语音识别、文本分析串行占用模型资源；`device = "auto"` 优先使用 Apple GPU，
没有可用 Apple GPU 时使用 CPU，也可以明确设置 `cpu` 或 `mps`。
模型版本与全部依赖固定，下载完成后的日常处理强制离线并关闭遥测。

首次运行 `./setup-speakers.sh`。官方模型需要在
[模型页面](https://huggingface.co/pyannote/speaker-diarization-community-1) 登录账号并接受访问条款。
本机凭证未配置时，运行 `./setup-speakers.sh --authorize`，按终端提示在浏览器配对；
只临时申请已获准公开受限模型的读取权限，不申请仓库管理、私有仓库或账单权限，不保存账号令牌。
不要把令牌放进配置或聊天。
这一步未完成时，索引显示“说话人模型待准备”，不会阻塞原始转写。
安装完成后可用 `./run.sh check-speaker-model` 校验模型。

`config.toml` 的 `[speakers]` 控制此功能：`enabled = true` 开启；

补做后运行 `./run.sh enrich <任务标识>` 可立即更新整理稿和分析稿，也可以在下一次扫描时一并补齐。

说话人按声音首次出现的顺序编号为“说话人 1、说话人 2”等，编号仅在单份录音内有效，
不自动识别真实姓名、性别、职务或跨录音身份。本版暂不提供联系人声纹库或手动姓名映射。
阅读稿、完整稿、TXT、字幕和后续整理稿显示对应编号；说话人切换时独立成段，
整理模型不会合并不同人的段落，分析稿的时间引用也带说话人信息。
仍无法可靠对齐的文字显示“说话人待确认”；重叠声音显示“重叠发言（归属待确认）”，
不会强行把抢话内容分配给一个人。原音频没有被分离成多条人声，重叠内容本身仍可能漏识别。

既有 `segment-N` 原始引用锚点保留，新增 `turn-N` 用于分人后的细分引用。

自动识别为 1 → 2 → 1 → 2，原文保留、重复处理缓存复用通过。
这只验证基本流程和该合成样本，不能推导真实会议的说话人准确率；验收记录在 `verification/speakers/latest.txt` 指向的报告。
