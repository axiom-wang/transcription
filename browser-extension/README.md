# 听记 · 标签页录音

同时独立录制多个浏览器标签页的音频，保存为本机 `.mkv` 文件（必要时回退为 `.webm`）。每条录音可一键交给听记，进入现有的转写、文稿优化和说话人处理队列。

拓展只通过 Native Messaging 连接本机听记，不上传音频到远程服务。听记模型须提前安装，日常处理使用本地模型。被录制的网站自身仍可能联网。

## 安装

1. 在听记项目完成安装，确保 `.venv/bin/python` 可用。在**听记项目根目录**运行：

   ```bash
   .venv/bin/python scripts/install_browser_extension.py
   ```

2. 在 Chrome 打开 `chrome://extensions`，开启「开发者模式」，点击「加载已解压的扩展程序」，选择本目录 `browser-extension/`。
3. 将拓展固定到工具栏，打开侧栏，设置区应显示「听记连接器已安装」。

安装脚本可重复运行。默认安装到当前用户的 Chrome 配置，同时兼容已有的 Chrome Beta/Canary、Chrome for Testing、Chromium、Edge、Brave、Arc 配置。其他浏览器须在各自的拓展管理页加载本目录。安装后新增浏览器或移动听记项目目录时，请重新运行脚本。宿主只允许本拓展的固定 ID 连接；公钥已随拓展保存，无需生成或保管私钥。

## 使用

1. 切换到要录音的标签页，点击拓展图标（或按 `Alt+Shift+R`；macOS 为 `Option+Shift+R`），逐个授权。浏览器内部页面等受保护页面无法录制。
2. 在侧栏开始录制。每个标签页分别录制，可单独停止，也可全部停止。`Alt+Shift+S` 开始或停止全部。
3. 文件保存在「下载/标签页录音/会话目录/」下。等待下载完成，点击该录音旁的「在听记中处理」。
4. 出现「已加入听记队列」后，点击「打开听记」查看队列和处理结果。队列确认只表示接收成功，转写是否完成请在听记查看。相同内容已完成转写时，再次发送会显示「已有相同录音，直接复用」。

「停止后自动送入听记」默认关闭，开启后仅在下载完成时自动发送，设置会保留。发送失败可在录音行重试，手动发送不受自动开关影响。「录制时播放声音」独立控制回放，默认静默录制，不改变保存的音频。录音面板的列表按浏览器会话保存，重新加载拓展会清除授权与列表；已下载文件仍在本机，可在听记手动导入。

发现未保存的录音时，可以在恢复提示中保存，再走同样的听记发送流程。下载记录或文件已被删除、文件尚未下载完成时，不会发送。

## 常见问题

- **未安装听记连接器**：运行上面的安装命令，再重新打开面板检测。确认加载的是听记仓库内的拓展目录，且浏览器已有的配置目录已被安装脚本识别。
- **无法连接听记**：确认项目 `.venv` 可用；若移动了项目目录，重新运行安装脚本。日志在听记项目的 `state/logs/native-host.log`。
- **找不到录音文件**：下载完成后如果移动或删除了文件，Chrome 的原路径将失效；可在听记直接导入移动后的文件。
- **队列失败或说话人模型未准备好**：到听记中查看具体错误并重试。开启自动发送只负责导入，不会更改听记当前模型和处理设置。

## 开发与验证

纯 JavaScript、Manifest V3，无运行时 npm 依赖。Chrome 116 或更新版本。

```bash
cd browser-extension
npm test
```

Node 测试覆盖录音与下载消息链、手动/自动发送、缺少连接器、失败重试、重复发送、恢复保存和后台唤醒。真实标签页捕获和 Native Messaging 连接仍需在用户 Chrome 验证：录制播放语音的标签页约 10 秒，停止后发送，确认听记队列接收并完成转写，再次发送确认复用。
